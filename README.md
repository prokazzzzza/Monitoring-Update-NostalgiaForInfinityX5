# 📁 Структура проекта
Проект состоит из нескольких файлов и папок, важные из которых:

Dockerfile — описание конфигурации для сборки Docker-образа.
.env — конфигурационный файл, в котором настраиваются параметры для работы с проектом (токены, пути и т.д.).
Update/ — папка для хранения загруженных обновлений стратегии.
main.py — поддерживаемая точка входа с модулями app/ и config/. Docker запускает именно её.

Сохранённые `MonitoringForUpdateStratagiaRU.py` и `MonitoringForUpdateStratagiaENG.py`
служат историческими образцами поведения. Они не получают перечисленные ниже
исправления авторизации и журналирования; не используйте их как рабочую точку входа.

## Безопасная конфигурация модульной версии

Требуется Python 3.12. `LANGUAGE=RU` или `LANGUAGE=ENG` выбирает язык во время
запуска, без пересборки образа. `.env` загружается только из папки приложения;
секреты не копируются в Docker-образ. Сервис использует исходящие подключения и
не публикует входящие порты.

Все команды и кнопки разрешены только для числового `CHAT_ID`. Участники
настроенного группового чата имеют те же права: для личного управления используйте
ID личного чата. `FREQTRADE_CHAT_ID` можно задать отдельно; без него сохраняется
совместимый fallback на `CHAT_ID`. Ответ Telegram `ok=true` подтверждает доставку
команды, но не её применение в Freqtrade.

`FILE_URL` и необязательный `BLACKLIST_FILE_URL` должны указывать на HTTPS
`raw.githubusercontent.com`, без перенаправлений. `REPO_URL` имеет вид
`owner/repository`, `REMOTE_FILE_PATH` — путь относительно ветки `main`.
Для blacklist по-прежнему задаются все три параметра:
`BLACKLIST_FILE_URL`, `BLACKLIST_LOCAL_FILE_PATH`, `BLACKLIST_REMOTE_FILE_PATH`.
Загружаемые данные blacklist сравниваются непосредственно с локальным файлом;
одинаковые байты не перезаписываются даже по ручной кнопке. Файлы `.json` должны
содержать JSON object/list, текстовые списки — непустой UTF-8, не HTML.

Каталоги локальных файлов должны существовать и быть доступны для записи.
Имена файлов стратегии, blacklist и служебного маркера не должны пересекаться.
Загрузка ограничена 8 MiB и 30 секундами на попытку, содержимое проверяется до
атомарной замены. Неизвестная локальная/удалённая версия останавливает плановое
обновление; первоначальная загрузка выполняется явно кнопкой скачивания.

Ручная загрузка не отправляет reload. Плановая отправляет одну команду только
после успешного пакета изменений стратегии/blacklist. Перед изменением файлов
создаётся `.monitoring-reload-pending.json` рядом со стратегией (обычно `Update/`).
Этот каталог должен сохраняться через Docker volume. При частичном обновлении,
отмене или неподтверждённой доставке маркер переживает перезапуск и блокирует
автоматические повторы. Проверьте файлы и Freqtrade, затем используйте отдельную
ручную кнопку reload. Не удаляйте маркер для обхода проверки. Подтверждённая
первая автоматическая или ручная доставка очищает маркер; runtime всё ещё
проверяется отдельно. Отсутствие маркера само по себе не доказывает runtime health.

`CHECK_INTERVAL` по умолчанию 3600 секунд (1–604800), `RETRY_LIMIT` — 3 (1–10),
`RETRY_DELAY` — 5 секунд (1–3600), `TIMEZONE` — UTC. Некорректная конфигурация
останавливает запуск до Telegram-соединения, без вывода значений секретов.

## Автономные проверки

Из корня репозитория после установки зависимостей и pytest:

```bash
python -m pytest tests -q
```

Тесты используют временные файлы и сетевые заглушки, запрещают socket-соединения
и не запускают рабочего бота, Freqtrade или vendored strategy. CI отдельно
проверяет зависимости и собирает Docker-образ без запуска контейнера.

# ⚡ Как работает скрипт
### Мониторинг обновлений стратегии:

Скрипт периодически проверяет репозиторий GitHub на наличие изменений в файле стратегии, используя указанный FILE_URL.
Если версия стратегии изменяется, файл обновляется в локальной папке LOCAL_FILE_PATH.
Если обновление найдено, скрипт отправляет уведомление в Telegram.

### Автоматическая перезагрузка Freqtrade:

После того как обновление стратегии будет обнаружено и файл будет скачан, скрипт автоматически отправляет команду на перезагрузку бота Freqtrade с использованием Telegram-бота 🤖.
Для этого используется токен, указанный в переменной FREQTRADE_BOT_TOKEN. Бот отправляет команду на перезагрузку стратегии, чтобы новая версия вступила в силу.
Использование Freqtrade:

С помощью Telegram-бота можно проверять новую версию стратегии, просматривать коммиты скачаной стратегии, а так же перезапускать Freqtrade.

# ⏲️ Настройка интервала обновлений
В .env файле вы можете настроить переменную CHECK_INTERVAL, которая определяет, как часто будет проверяться обновление стратегии. Рекомендуется устанавливать значение в пределах нескольких минут.
